01What is HTML?

HTML (HyperText Markup Language) is the skeleton of every website. It uses tags wrapped in angle brackets to tell the browser: "this is a heading", "this is a link", "this is an image".

Every tag usually comes in a pair — an opening tag and a closing tag (closing tags have a /). Some tags are void (self-closing) — they have no closing tag.

CODE
<p>This is a paragraph</p>
<h1>This is a heading</h1>

<!-- void tags need no closing tag: -->
<img src="photo.jpg" alt="A photo">
<br>  <input>  <hr>  <meta>
RESULT

This is a paragraph

This is a heading

Void tags (img, br, hr, meta, input…) never have a closing tag.

Remember: opening tag <p> + content + closing tag </p>. HTML is forgiving — it won't crash, but mistakes render weirdly. Fix them early!

02How the Web Works

When you open a website, four things happen in under a second:

  1. You type a URL like https://example.com in the browser.
  2. The browser asks a server (a computer that stores the site) for the HTML file.
  3. The server sends back the file.
  4. The browser reads the HTML and renders it into the page you see.
CODE
https://example.com/products?id=42#reviews
  |_____________|  |____|  |__|  |____|
       domain        path  query  fragment
  (which site)  (which page) (data)(scroll to)
RESULT
🌐 You → 🧭 Browser → 📡 Internet → 🖥️ Server

The browser is a translator: it reads HTML (structure) + CSS (style) + JavaScript (behavior) and draws the page.

Key idea: HTML = skeleton (content & meaning). CSS = clothes (looks). JavaScript = muscles (actions). This page is built from exactly those three!

03Page Structure (the skeleton)

Every HTML page follows this same skeleton. Copy this to start any project:

CODE
<!DOCTYPE html>          <!-- HTML5 declaration -->
<html lang="en">        <!-- root element, lang = language -->
<head>                   <!-- hidden settings -->
    <meta charset="UTF-8">
    <title>My First Page</title>
</head>
<body>                   <!-- visible content -->
    <p>Hello, World!</p>
</body>
</html>
RESULT

What the <body> renders:

Hello, World!

Everything in <head> is invisible on the page. It's instructions for the browser and search engines.

TagPurpose
<!DOCTYPE html>tells the browser "this is HTML5" (must be the very first line)
<html>the root element that wraps everything
<head>metadata — title, charset, styles, scripts
<body>everything the visitor sees

04The <head> Section & Meta Tags

The <head> holds invisible information. <meta> tags describe your page to browsers and search engines.

CODE
<head>
    <meta charset="UTF-8">              <!-- emoji & symbols -->
    <meta name="viewport"
          content="width=device-width,
                   initial-scale=1.0">  <!-- mobile friendly -->
    <meta name="description"
          content="Learn HTML free">    <!-- shown on Google -->
    <meta name="author" content="You">
    <title>My Page</title>             <!-- browser tab -->
    <link rel="icon" href="favicon.ico"> <!-- tab icon -->
    <link rel="stylesheet" href="style.css">
    <style> body { color: blue; } </style>
    <script src="app.js"></script>
</head>
RESULT

You can't see the head… but you can see its effects:

🖥️ This tab's title is "HTML Notes — Every Tag, Every Topic"

📱 The viewport meta makes this page fit phone screens

🔍 The description meta is what Google shows under your link

✳️ The favicon is the tiny icon next to the tab title

Most useful meta tags

Meta tagWhat it does
charset="UTF-8"supports every language & emoji — always include
name="viewport"makes pages responsive on mobile — always include
name="description"the snippet Google shows in results
name="keywords"old SEO practice, Google ignores it now
name="author"who wrote the page
http-equiv="refresh" content="5;url=https://x.com"auto-redirect after 5 seconds
property="og:title"title shown when shared on WhatsApp/Facebook

Note: <style> and <script> are the only head tags that do affect what you see — styles change looks, scripts add behavior.

12<div> & <span> — Generic Boxes

<div> is a block container: full width, stacks vertically. <span> is an inline wrapper: sits inside text, only as wide as its content.

CODE
<div class="box-red">
    <p>I am inside a div</p>
    <p>Divs stack full-width</p>
</div>

<div class="box-blue">
    Second div, new line
</div>

<p>Text with a
    <span class="span-red">red span</span>
    and a <span class="span-blue">blue span</span>
    inline in the same line.
</p>
RESULT

I am inside a div

Divs stack full-width

Second div, new line

Text with a red span and a blue span inline in the same line.

Rule of thumb: div = big blocks of the page. span = small inline bits of text. And when a tag with meaning exists (header, p, li…), use that instead of div!

13Semantic Layout Tags

HTML5 gives us meaningful containers instead of <div> everywhere. Search engines and screen readers understand these instantly.

CODE
<header>   <!-- top: logo, title --></header>
<nav>      <!-- menu / links --></nav>

<main>     <!-- main content (1 per page) -->
    <section> <!-- a themed block --></section>
    <article> <!-- self-contained post --></article>
    <aside>   <!-- side info / ads --></aside>
</main>

<footer>   <!-- bottom: copyright --></footer>
RESULT
header — logo & title
nav — Home · About · Contact
section — main content
aside — sidebar
footer — © 2026
TagMeaning
<header>top area: logo, page title, intro
<nav>navigation links / menu
<main>the main content — only one per page
<section>a themed group of content (usually has a heading)
<article>self-contained content: blog post, news, comment
<aside>side content: sidebar, related links, ads
<footer>bottom: copyright, contact, links
<figure> + <figcaption>an image/diagram with a caption (see section 17)
<details> + <summary>click-to-expand box (see section 26)
<dialog>a popup window (see section 26)
Why it matters: Google reads <nav> to find your menu, <article> to index your posts. Screen readers jump straight to <main>. Semantic HTML = better SEO + better accessibility — for free.

    28Accessibility — HTML for everyone

    ~15% of the world has a disability. Screen readers read your page aloud; keyboards navigate it. Good HTML = accessible HTML. The basics:

    CODE

<img src="dog.jpg"
     alt="A golden retriever playing">

<!-- label: what the field is -->
<label for="email">Email</label>
<input type="email" id="email">

<!-- aria: extra info for readers -->
<button aria-label="Close window">✕</button>

<!-- role: what an element is -->
<div role="alert">Error!</div>

<!-- skip link for keyboard users -->
<a class="skip-link" href="#content">
    Skip to content
</a>
    RESULT

    Accessibility checklist:

    • ✅ alt on every image
    • ✅ <label> for every input
    • ✅ Real buttons for buttons (not divs)
    • ✅ One <h1>, logical heading order
    • ✅ Semantic tags (nav, main, footer)
    • ✅ Good color contrast (dark text on light)
    • ✅ lang attribute set
    • ✅ Text alternative for video (captions)
    Mindset: build for everyone first, add fancy stuff second. Accessible sites rank better on Google too — accessibility and SEO agree with each other!

    30Best Practices & Next Steps

    ✅ Do

    • Always close your tags — a missing </div> is the #1 beginner bug.
    • Always add alt to images and label to inputs.
    • Use semantic tags (<header>, <main>) instead of plain <div>.
    • One <h1> per page; keep heading order.
    • Indent nested tags — readable code = fewer bugs.
    • Style with CSS, never with <br> or <b>.
    • Validate your code at validator.w3.org.

    ❌ Avoid

    • Tables for layout (use CSS) and <font> tags (gone anyway).
    • Inline style="..." everywhere — use classes.
    • Skipping heading levels or using <h1> for size.
    • Forgetting name on inputs — then the data never sends!
    • Deep div-nesting soup: <div><div><div>…

    31File Paths & Folder Structure

    Knowing how to point to files is half of HTML. Imagine this folder:

    CODE
    my-site/                 <!-- project root -->
├── index.html           <!-- the homepage -->
├── about.html
├── style.css
├── images/
│   ├── logo.png
│   └── gallery/
│       └── photo.jpg
└── pages/
    └── blog.html
    RESULT

    Path rules:

    • logo.png — same folder as the page
    • images/logo.png — one folder down
    • ../logo.png — one folder up
    • /logo.png — from the website root
    • https://… — full URL (absolute)
    CODE
    <!-- from index.html -->
<img src="images/logo.png" alt="Logo">

<!-- from pages/blog.html
     (same folder level as images/) -->
<img src="../images/logo.png"
     alt="Logo">
<link rel="stylesheet"
      href="../style.css">

<!-- back to homepage -->
<a href="../index.html">Home</a>

<!-- full URL (absolute) -->
<img src="https://mysite.com/
     images/logo.png">
    RESULT

    The golden rules:

    • . = current folder, .. = parent folder
    • Relative paths keep working when you upload the site
    • Always use / (forward slash), never \
    • No spaces in file names — use - (my-photo.jpg)
    • Case matters: Logo.png ≠ logo.png on servers
    Beginner trap: <img src="images/logo.png"> breaks if the image is actually one folder up. When an image won't load, first check the path — it's the #1 cause!

    34Content Categories — how the browser classifies tags

    MDN organizes every element into content categories. They decide where a tag can live and what it can contain. You don't need to memorize them — just understand the big three:

    CODE
    <!-- FLOW: most things you put in body -->
<p>Flow</p>  <div>Flow</div>
<ul><li>Flow</li></ul>

<!-- PHRASING: inline bits inside text -->
<p>Inside a paragraph you can
   put <strong>phrasing</strong>
   and <a href="#">links</a>.</p>

<!-- EMBEDDED: media & external content -->
<img src="a.jpg" alt="a">
<iframe src="b.html"></iframe>

<!-- INTERACTIVE: things users click/type -->
<button>Click</button>
<a href="#">Link</a>
<input type="text">
    RESULT

    The categories (simplified):

    • Metadata — head stuff (title, meta, link)
    • Flow — most body content
    • Sectioning — creates page structure (header, section)
    • Heading — h1–h6, hgroup
    • Phrasing — text-level tags (em, span, a)
    • Embedded — img, iframe, video, svg
    • Interactive — clickable/typeable (a, button, input)
    • Palpable — content a user can actually see/touch
    CODE
    <!-- THE BIG RULE this explains: -->
<p>
    <div>WRONG!</div>
    <!-- a div (flow) can't sit inside
         a p (phrasing only) -->
</p>

<p>
    <span>RIGHT!</span>
    <!-- span is phrasing, allowed -->
</p>

<!-- ul can only contain li -->
<ul>
    <li>item 1</li>
    <li>item 2</li>
</ul>
    RESULT

    Why it matters:

    Browsers are forgiving — but putting a block inside a paragraph

    secretly closes the paragraph and restructures your page. That's why a stray <div> inside <p> causes weird gaps and jumps.

    Knowing the categories = understanding why pages break.

    Beginner takeaway: phrasing content goes inside text. Flow content goes inside body/containers. Interactive can't be nested inside other interactive (no <a> inside <button>!).

    37Performance — make pages fast

    Slow pages lose visitors: every extra second = more people leaving. Big wins, small effort:

    CODE
    <!-- 1. lazy load images below the fold -->
<img src="big.jpg" loading="lazy">

<!-- 2. always set width+height -->
<!-- stops layout jumping while loading -->
<img src="x.jpg" width="400"
     height="300">

<!-- 3. preload critical resources -->
<link rel="preload"
      href="font.woff2"
      as="font">

<!-- 4. compress images (WebP) -->
<picture>
    <source srcset="photo.webp"
            type="image/webp">
    <img src="photo.jpg" alt="photo">
</picture>
    RESULT

    Performance checklist:

    • ✅ loading="lazy" on images
    • ✅ width/height set on images
    • ✅ compress images (tinyjpg, squoosh)
    • ✅ modern format: WebP/AVIF
    • ✅ few files, not many tiny ones
    • ✅ CSS & JS at the right place
    • ✅ test with Lighthouse (F12 → Lighthouse)
    Rule of thumb: images are 60-70% of a typical page's weight. Optimizing images alone makes most sites feel instant.
