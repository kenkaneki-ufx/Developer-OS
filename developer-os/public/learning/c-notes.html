01What is C?

C is a compiled, systems-level language created in 1972 by Dennis Ritchie. The Linux kernel, Windows, databases, game engines and every other language's runtime are written in it. Learning C teaches you how computers actually work — memory, addresses, and all.

CODE — hello.c
#include <stdio.h>

int main(void) {
    printf("Hello, world!\n");
    return 0;
}
OUTPUT
$ gcc hello.c -o hello $ ./hello Hello, world!
Why C?What it means
Fast & smallNo hidden runtime — the code you write is close to the machine
Manual memoryYou decide when to allocate and free — full control, full responsibility
The foundationPython, Java, JS runtimes are written in C
PointersC's superpower — direct access to memory addresses
C does NOT protect you. No automatic memory management, no bounds checking. This is a feature for professionals — and a trap for beginners. That's what these notes teach you to handle.

02Setup & Compiling

C has no interpreter — every change means compiling. Install a compiler once: Windows → MinGW-w64 (or use VS Code + the C/C++ extension), Mac → Xcode Command Line Tools, Linux → sudo apt install gcc.

TERMINAL — the daily loop
$ gcc hello.c -o hello # compile → binary $ ./hello # run it Hello, world! $ gcc -Wall -Wextra hello.c -o hello # warnings on! $ gcc -g hello.c -o hello # debug symbols for gdb
THE PIPELINE
hello.c ──compiler──> hello.o ──linker──> hello # 1. preprocessor: pulls in #include files # 2. compile: .c → machine code (.o) # 3. link: glue .o files + libraries → executable

Every program needs these two things

#include <stdio.h>   // standard input/output functions

int main(void) {        // execution starts here
    return 0;            // 0 = success (to the OS)
}
Compile errors are normal. The compiler tells you the file and line — read it, fix it, recompile. Speed comes from this loop: edit → gcc → run.

03printf() — Your First Function

printf("format", values) prints text with format specifiers — the placeholders that decide how a value is displayed. The specifier MUST match the type:

CODE
#include <stdio.h>

int main(void) {
    int age = 17;
    float pi = 3.14159;
    char letter = 'A';

    printf("I am %d years old\n", age);
    printf("Pi is %.2f\n", pi);
    printf("Letter %c comes before %c\n", letter, letter + 1);
    printf("In hex: %x\n", age);
    return 0;
}

05Constants & sizeof()

Three ways to make a value that can't change, plus sizeof() — the operator that tells you exactly how many bytes anything uses:

CODE
#define MAX_SCORE 100          // preprocessor constant

const int PASS = 40;          // const variable

enum { RED, GREEN, BLUE };     // enum constants 0,1,2

int main(void) {
    printf("int: %zu bytes\n", sizeof(int));
    printf("char: %zu byte\n", sizeof(char));
    printf("double: %zu bytes\n", sizeof(double));
    printf("score: %d, pass? %d\n", MAX_SCORE, PASS);
    return 0;
}
OUTPUT
int: 4 bytes char: 1 byte double: 8 bytes score: 100, pass? 40

sizeof works on variables too

int arr[10];
printf("array: %zu bytes → %zu elements\n",
        sizeof(arr), sizeof(arr) / sizeof(arr[0]));
// 40 bytes → 10 elements — the classic length trick!
Which to use? const for typed constants in C code, #define for values used by the preprocessor (arrays sizes), enum for groups of related named values.

06Operators

Arithmetic works like math — with two traps: integer division truncates, and % is remainder. Then come comparison, logic, and the sneaky ++:

CODE
int a = 5, b = 2;

printf("%d\n", a / b);        // 2 — integer division TRUNCATES!
printf("%.1f\n", a / (float)b); // 2.5 — cast makes it float
printf("%d\n", a % b);        // 1 — remainder
printf("%d\n", a < b || a == 5);  // 1 (true) — OR
printf("%d\n", a > b && b > 0); // 1 (true) — AND
printf("%d %d\n", a++, ++b); // post: 5 then 6 | pre: b is 3 now
printf("%d\n", !a > 0 ? a : -a); // ternary
OUTPUT
2 2.5 1 1 1 5 3 5
CategoryOperators

Incrementi++ ++i i-- --i (post vs pre)

== vs =: if (x = 5) ASSIGNS 5 and is always true! The compiler warns with -Wall. Write if (5 == x) to catch it instantly.

07Conditions — if / else / switch

In C, if takes a number: 0 = false, anything else = true. Use braces even for one-liners — it saves real bugs:

CODE
int age = 17;

if (age < 13) {
    printf("Child\n");
} else if (age < 20) {
    printf("Teenager\n");
} else if (age < 65) {
    printf("Adult\n");
} else {
    printf("Senior\n");
}

// switch — for many exact values
switch (age / 10) {
    case 1: printf("Teen\n"); break;
    default: printf("Other\n"); break;
}
LIVE — slide the age

switch falls through! Forgetting break runs the next case too — the classic C bug. Always break (or use return).

08Loops — for / while / do-while

Three loops, one rule of thumb: for when you know the count, while when you're waiting for a condition, do-while when the body must run at least once:

CODE
// for: init; condition; step
for (int i = 0; i < 5; i++) {
    printf("%d ", i);          // 0 1 2 3 4
}

// while: keep asking until the right answer
int guess = -1;
while (guess != 42) {
    scanf("%d", &guess);  // &guess = "address of guess"
}

// do-while: runs once no matter what
int n = 0;
do { printf("n=%d ", n); n++; } while (n < 3);
OUTPUT
0 1 2 3 4 n=0 n=1 n=2

break / continue / nested

// sum 1..100 but skip multiples of 3, stop at 90
int total = 0;
for (int i = 1; i <= 100; i++) {
    if (i % 3 == 0) continue;   // skip this round
    if (i > 90) break;          // exit the loop
    total += i;
}
printf("%d\n", total);
Infinite loop: while (1) never stops unless something inside breaks out. Make sure the condition can actually become false.

09Functions — return type, name, params

A function in C is declared as return_type name(params). Arguments are passed by value — the function gets copies. To change the caller's data you need pointers (section 16):

CODE
#include <stdio.h>

int add(int a, int b);    // prototype: tells main what exists

int main(void) {
    int sum = add(2, 3);
    printf("%d\n", sum);        // 5
    return 0;
}

int add(int a, int b) {
    return a + b;             // result handed back
}
OUTPUT
5

Shapes of functions

double f(double)a doublesqrt(9) → 3.0
Prototypes exist so main can call a function defined later in the file. Without it, the compiler guesses — and that's where bugs are born. In multi-file projects, prototypes live in header files (section 26).

10Scope & Storage Classes

Where a variable lives decides who can see it and how long it survives. Three keywords cover 95% of real code: auto (default), static, extern:

CODE
int global = 10;            // global: visible everywhere

int counter(void) {
    static int n = 0;    // static: keeps value between calls!
    n++;
    return n;
}

int main(void) {
    printf("%d %d %d\n", counter(), counter(), counter());
    printf("global=%d\n", global);
    return 0;
}

11Arrays — Blocks of Same-Type Data

An array is a contiguous block of memory holding N values of one type. Indexing starts at 0, and there's no built-in bounds check — go past the end and you corrupt memory:

CODE
int scores[5] = {90, 85, 78, 92, 88};

scores[0] = 95;                 // update first element

int total = 0;
for (int i = 0; i < 5; i++) {
    total += scores[i];
}
printf("avg: %.1f\n", total / 5.0);

// 2D array: rows × cols
int grid[2][3] = {{1, 2, 3}, {4, 5, 6}};
printf("%d\n", grid[1][2]);   // 6
OUTPUT
avg: 87.6 6

The length trick

int arr[] = {3, 1, 4, 1, 5};
size_t n = sizeof(arr) / sizeof(arr[0]);  // 5
// Works where the array is declared. NOT inside functions
// that receive it as a parameter — it decays to a pointer (sec 15).
Out of bounds: scores[9] = 1 compiles fine and may work for a while — then corrupts memory mysteriously. No exception is thrown in C. Check your indexes!

12Strings — char Arrays with a Secret

There is no string type in C. A string is an array of chars ending with '\0' (the null terminator). Every string function walks the array until it finds that zero byte:

CODE
#include <string.h>

char name[20] = "Lina";   // {'L','i','n','a','\0', ...}

printf("%zu\n", strlen(name));      // 4 — NOT counting '\0'
printf("%zu\n", sizeof(name));      // 20 — the array capacity

char full[40];
strcpy(full, name);               // copy (not = !)
strcat(full, " Khan");            // append
printf("%s\n", full);             // Lina Khan
printf("%d\n", strcmp(name, "Mina"));  // > 0 → name is bigger
OUTPUT
4 20 Lina Khan 1
FunctionDoes
strlen(s)length without '\0'
strcpy(dst, src)copy (dst must be big enough!)
strcat(dst, src)append to dst
strcmp(a, b)0 if equal, <0 / >0 otherwise
sprintf(buf, fmt, …)printf into a string
Buffer overflow: strcpy doesn't check space. Copying 40 chars into a 20-char buffer corrupts memory. Prefer strncpy(dst, src, size-1) and always keep room for '\0'.

13Pointers — The Core Idea

Every variable lives at a memory address. A pointer is just a variable that stores an address. Two operators run the show: & (address-of) and * (dereference — "go to that address"):

CODE
int x = 42;
int *p = &x;    // p stores the ADDRESS of x

printf("x = %d\n", x);
printf("&x = %p\n", (void*)&x);  // address
printf("p = %p\n", (void*)p);      // same address!
printf("*p = %d\n", *p);          // 42 — go get the value

*p = 99;          // change x THROUGH the pointer
printf("x = %d\n", x);   // 99!

14Pointer Arithmetic — p+1 is NOT address+1

Adding to a pointer moves by the size of what it points to. int *p → p + 1 jumps 4 bytes; char *c → c + 1 jumps 1 byte. This is why p[i] is exactly *(p + i):

CODE
int arr[3] = {10, 20, 30};
int *p = arr;              // arr == &arr[0]

printf("%d\n", *p);             // 10
printf("%d\n", *(p + 1));       // 20 — 4 bytes forward
printf("%d\n", p[2]);          // 30 — same thing

// walk the array with a pointer
for (int *q = arr; q < arr + 3; q++) {
    printf("%d ", *q);
}
OUTPUT
10 20 30 10 20 30
ExpressionMeans
p + 1next element (sizeof(int) bytes later)
p - arrelement index (pointer difference)
p++advance to next element
*p++use value, then advance (idiom!)
Only within the array: arithmetic past one-past-the-end is undefined behavior. q < arr + 3 above is safe; q <= arr + 3 and dereferencing at the end is not.

15Pointers & Arrays — The Decay

An array's name decays to a pointer to its first element in most expressions. That's why passing an array to a function really passes a pointer — and why the function can modify the caller's data:

CODE
void double_all(int *a, int n) {
    for (int i = 0; i < n; i++)
        a[i] *= 2;            // changes the ORIGINAL array
}

int main(void) {
    int nums[] = {1, 2, 3};
    double_all(nums, 3);   // nums decays → int*
    for (int i = 0; i < 3; i++)
        printf("%d ", nums[i]);  // 2 4 6
    return 0;
}
OUTPUT
2 4 6

Key rule: you can't get the length of a passed array

void bad(int a[]) {   // looks like an array…
    sizeof(a) / sizeof(a[0]);  // …but a is a POINTER → wrong!
}

// Always pass the length alongside the array:
void good(int a[], size_t n) { /* … */ }
Constant vs pointer: char *s can point anywhere; const char *s promises not to modify what's pointed at — use it for strings you only read.

16Pointers & Functions — Pass by Reference

Arguments are copied (pass by value). To let a function change the caller's variables, pass their addresses. The eternal example — swap():

CODE
void swap(int *a, int *b) {
    int tmp = *a;   // read what a points to
    *a = *b;
    *b = tmp;
}

int main(void) {
    int x = 1, y = 2;
    swap(&x, &y);     // pass addresses!
    printf("x=%d y=%d\n", x, y);   // x=2 y=1
    return 0;
}
LIVE — try both versions

a = 1   b = 2

When do you need pointers as parameters? (1) to modify a caller variable, (2) to avoid copying a huge struct, (3) to return something from a helper via an out-parameter like scanf("%d", &age).

17Dynamic Memory — malloc, calloc, free

Arrays are fixed at compile time. When you need a size you only know at runtime, ask the heap: malloc hands back a block of memory (or NULL on failure). Every malloc needs a matching free:

CODE
#include <stdlib.h>

int n;
scanf("%d", &n);

int *nums = malloc(n * sizeof(int));
if (nums == NULL) {            // always check!
    printf("Out of memory\n");
    return 1;
}

for (int i = 0; i < n; i++)
    nums[i] = i * i;              // use it like an array!

printf("%d\n", nums[n - 1]);
free(nums);                      // give it back — or it leaks
nums = NULL;                     // avoid dangling pointer
LIVE — size it yourself

n = 5

FunctionDoes
malloc(n)n raw bytes, uninitialized
calloc(n, size)n × size bytes, zeroed
realloc(p, n)resize an existing block
free(p)release the block
The golden rules: check for NULL, free exactly once, free in the same layer you allocated, and always use sizeof — never hardcode byte counts.

19Structs — Your Own Data Types

A struct bundles related fields into one type. It's C's way of making a "student", "point", or "bank account" — one variable, many attributes:

CODE
struct Student {
    char name[30];
    int age;
    float gpa;
};                    // note the semicolon!

int main(void) {
    struct Student s1 = {"Lina", 17, 3.8};
    struct Student s2;
    strcpy(s2.name, "Sam");
    s2.age = 16;
    s2.gpa = 3.5;

    printf("%s %d %.1f\n", s1.name, s1.age, s1.gpa);

    struct Student class[30];   // array of structs!
    class[0] = s1;
    return 0;
}
OUTPUT
Lina 17 3.8

Nested structs & copying

struct Point { int x, y; };
struct Rect  { struct Point tl, br; };

struct Rect r = {{0, 0}, {10, 10}};
struct Rect copy = r;   // structs copy wholesale with =
Padding: the compiler may insert unused bytes between fields so the CPU reads fast. sizeof(struct) can be bigger than the sum of its fields — that's normal.

20Pointers to Structs — The -> Arrow

Structs get big fast. Passing by value copies the whole struct; passing a pointer passes 8 bytes. The arrow -> is shorthand for (*p).field:

CODE
struct Student { char name[30]; int age; float gpa; };

void print_student(const struct Student *s) {
    printf("%s — %d — %.1f\n", s->name, s->age, s->gpa);
    // const = promise not to modify (read-only)
}

void birthday(struct Student *s) {
    s->age++;               // modifies the ORIGINAL
}

int main(void) {
    struct Student s = {"Lina", 17, 3.8};
    print_student(&s);
    birthday(&s);
    printf("age now: %d\n", s.age);   // 18
    return 0;
}
OUTPUT
Lina — 17 — 3.8 age now: 18

The arrow is just sugar

s->age    ==  (*s).age
// dereference s, then access the field
Rule of thumb: structs by value in printf-style small cases, pointers everywhere else — especially in arrays, linked lists (section 33) and recursive types.

21typedef — Cleaner Names

typedef gives a type a new name. It doesn't create a new type — just a shorter, clearer alias. Real codebases typedef their structs so you rarely type struct again:

CODE
typedef unsigned long ulong;
typedef struct Student Student;  // alias for 'struct Student'

struct Student {                 // define after? No — define first:
    char name[30];
    int age;
};
typedef struct Student Student;   // now 'Student' alone works

Student s = {"Lina", 17};    // no 'struct' keyword!

// combine definition + alias in one step (most common):
typedef struct {
    float x, y;
} Point;
OUTPUT
Lina 17
Style guide: typedef'd structs are usually named in CamelCase (Student, Point) while plain variables stay snake_case. Consistency beats cleverness.

22Unions & Enums

enum gives names to numbers (readable switches). union lets several fields share the same memory — its size is the largest member, and only one field is valid at a time:

CODE
enum Status { PENDING, ACTIVE, DONE };

enum Status st = ACTIVE;      // st == 1
switch (st) {
    case PENDING: printf("waiting\n"); break;
    case ACTIVE:  printf("running\n"); break;
    case DONE:    printf("finished\n"); break;
}

union Value {                 // 4 bytes — not 12!
    int i;
    float f;
    char c[4];
};
printf("%zu bytes\n", sizeof(union Value));  // 4
OUTPUT
running 4 bytes
The classic union trick
union Value v;
v.f = 1.5f;
for (int i = 0; i < 4; i++)
    printf("%02x ", v.c[i]);  // read the raw bytes of the float!
OUTPUT
00 00 c0 3f // 1.5 in IEEE 754 — little-endian
Union danger: writing v.i then reading v.f is undefined behavior — the bytes are the same but the meaning changed. Track which member is "active" yourself, or use tagged unions (a struct with an enum + union).

23Bitwise Operators — Working with Bits

C lets you manipulate the individual bits of an integer — the same trick used for permissions, flags and low-level hardware. & AND, | OR, ^ XOR, ~ NOT, << >> shift:

CODE
unsigned int a = 0b1100;   // 12
unsigned int b = 0b1010;   // 10

printf("%04x\n", a & b);    // 1000 = 8 (both bits)
printf("%04x\n", a | b);    // 1110 = 14 (either bit)
printf("%04x\n", a ^ b);    // 0110 = 6 (different bits)
printf("%04x\n", a << 1);   // 11000 = 24 (×2!)
printf("%04x\n", b >> 1);   // 101 = 5 (÷2)

// flag pattern: one bit per permission
#define READ  (1 << 0)   // 0001
#define WRITE (1 << 1)   // 0010
unsigned int perms = READ | WRITE;   // 0011
if (perms & WRITE) printf("can write\n");
LIVE — try it

a =   b =

Cheat sheet: x & 1 = last bit (odd/even), x & (x-1) clears the lowest set bit, 1 << n = bit n, x << 1 = x × 2. And XOR swaps two numbers without a temp!

24Type Conversion — Casting

Conversions happen implicitly (int → float, char → int) and explicitly with a cast (type)value. Casts don't change the value — they change how it's interpreted, and truncation can bite:

CODE
int x = 7;
int y = 2;

printf("%d\n", x / y);                // 3 — int division!
printf("%.1f\n", (float)x / y);       // 3.5 — cast x first
printf("%d\n", (int)3.99);          // 3 — truncates, not rounds
printf("%c\n", 65);               // A — int → char
printf("%d\n", (char)300);        // 44 — overflow wraps! ⚠️

int big = 2000000000 + 2000000000;  // UB — overflows int
OUTPUT
3 3.5 3 A 44

The promotion ladder (implicit)

char → int → long → long long → float → double
// smaller types get promoted to the larger before arithmetic
Signed overflow is undefined behavior — the compiler may do anything. Use unsigned or long long when values can get large, and check -Wconversion warnings.

25The Preprocessor — #include, #define

Before compiling, the preprocessor edits your source: lines starting with # are text-replacement commands. Three you'll use daily:

CODE
#include <stdio.h>     // paste in a header file

#define PI 3.14159        // replace PI with the text
#define AREA(r) (PI * (r) * (r))   // macro with a parameter

#ifdef DEBUG            // compile-time if
  printf("debugging…\n");
#endif

int main(void) {
    printf("%.2f\n", AREA(3));   // 28.27
    return 0;
}
OUTPUT
28.27 $ gcc -DDEBUG app.c -o app # defines DEBUG → debug prints on

Macro pitfalls (why const is safer)

#define BAD(x) x * x
BAD(2 + 3)   // → 2 + 3 * 2 + 3 = 11 😱 (expected 25)

#define GOOD(x) ((x) * (x))   // always wrap params in parens
GOOD(2 + 3)   // → 25 ✅
Rule: use #define for constants the preprocessor needs (array sizes, DEBUG flags, header guards) — prefer const and functions for everything else.

26Multi-File Programs — Headers & Linking

Real projects split into .c files (code) and .h headers (prototypes, structs, constants). The compiler compiles each .c separately; the linker glues them:

math_util.h — the interface
#ifndef MATH_UTIL_H      // header guard — include once
#define MATH_UTIL_H

int add(int a, int b);
int fact(int n);

#endif   // end guard
math_util.c — the implementation
#include "math_util.h"   // quotes = our file, not <>

int add(int a, int b) { return a + b; }
int fact(int n) {
    return n <= 1 ? 1 : n * fact(n - 1);
}
// main.c — only needs the header to use the functions
#include "math_util.h"
#include <stdio.h>

int main(void) {
    printf("%d %d\n", add(2, 3), fact(5));  // 5 120
    return 0;
}
TERMINAL — compile both files
$ gcc main.c math_util.c -o app $ ./app 5 120
Why the guard matters
# two files both #include "math_util.h" # without the guard → double declaration error # with #ifndef → included exactly once ✅
Convention: headers declare (prototypes, structs); .c files define (bodies). A header is a contract — other files trust it and never see the implementation.

27File I/O — Reading & Writing

fopen opens a file (or fails), then it's fprintf to write and fscanf/fgets to read. Always fclose and check the return of fopen:

CODE
FILE *f = fopen("notes.txt", "w");  // write mode
if (!f) { perror("open"); return 1; }

fprintf(f, "Hello, file!\n");
fprintf(f, "score: %d\n", 99);
fclose(f);

// read it back line by line
char line[100];
FILE *r = fopen("notes.txt", "r");
while (fgets(line, sizeof(line), r)) {
    printf("→ %s", line);
}
fclose(r);
OUTPUT
$ cat notes.txt Hello, file! score: 99 $ ./app → Hello, file! → score: 99
ModeMeaning
"r"read (error if missing)
"w"write — creates or empties
"a"append — adds to the end
"r+" / "w+"read and write
Always check fopen: fopen returns NULL when the file doesn't exist or you lack permission — using it unguarded crashes.

28Command-Line Arguments — argc & argv

Programs read their arguments through main: argc = argument count, argv = array of strings (a pointer to pointers — char**!). argv[0] is always the program name:

CODE
int main(int argc, char *argv[]) {
    printf("program: %s\n", argv[0]);
    printf("%d arguments\n", argc - 1);

    for (int i = 1; i < argc; i++)
        printf("arg %d: %s\n", i, argv[i]);

    return 0;
}
LIVE — ./app hello world 42

Convert args to numbers

#include <stdlib.h>
int n = atoi(argv[1]);       // "42" → 42 (0 if invalid)
long x = strtol(argv[1], NULL, 10);  // safer + error detection
Why char**? argv is an array of strings; each string is a char*; so the array is char*[], which decays to char** — the classic two-star pointer.

29Recursion — Functions That Call Themselves

A recursive function solves a problem by calling itself on a smaller version, until it hits a base case. Each call gets its own stack frame — too deep and you overflow the stack:

CODE
int fib(int n) {
    if (n < 2) return n;   // base case — stop
    return fib(n - 1) + fib(n - 2);
}

int fact(int n) {
    if (n <= 1) return 1;
    return n * fact(n - 1);
}

int main(void) {
    for (int i = 0; i < 8; i++)
        printf("%d ", fib(i));      // 0 1 1 2 3 5 8 13
    printf("\n%d\n", fact(5));      // 120
    return 0;
}
LIVE — fib(n) step by step

n = 10

Every recursion needs a base case, or it runs until the stack overflows (segfault). And naive fib(40) is exponential — memoize or use a loop. Some compilers optimize tail calls; most don't — prefer loops for deep recursion.

30Function Pointers — Code as Data

A pointer can also point at a function. Then you can pass behavior around — the secret behind callbacks and qsort's comparator:

CODE
int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int apply(int (*op)(int, int), int x, int y) {
    return op(x, y);             // call through the pointer
}

int main(void) {
    int (*fp)(int, int) = add;  // fp = add
    printf("%d\n", fp(2, 3));         // 5
    printf("%d\n", apply(mul, 4, 5)); // 20 — pass behavior
    return 0;
}
LIVE — pick the operation

op =   apply(op, 4, 5)

qsort — the real-world use

int cmp(const void *a, const void *b) {
    return *(int*)a - *(int*)b;  // cast, deref, compare
}
int arr[] = {3, 1, 4, 2};
qsort(arr, 4, sizeof(int), cmp);
// arr → {1, 2, 3, 4} — sorted by YOUR rule
Read it inside-out: int (*op)(int, int) = "*op is a function taking two ints and returning int". Without the parens, int *op(int,int) would be a function returning int*.

31Strings Deep — Buffers, Parsing, Danger

Strings are the #1 source of C bugs because they're fixed-size buffers with no built-in length. Master these and you'll dodge a decade of segfaults:

CODE
#include <string.h>

char name[10];
strncpy(name, "Alexander", sizeof(name) - 1);
name[sizeof(name) - 1] = '\0';   // guarantee termination!
printf("%s\n", name);           // Alexand" truncated safely

// parsing with strtok (splits a string)
char csv[] = "apple,banana,cherry";
char *tok = strtok(csv, ",");
while (tok) {
    printf("%s\n", tok);
    tok = strtok(NULL, ",");
}
LIVE — strtok in action

String literals vs arrays — a classic trap

char *s = "hello";   // points to a READ-ONLY literal
s[0] = 'H';        // ⚠️ undefined behavior (often segfault)

char a[] = "hello"; // a WRITABLE copy (6 bytes incl. '\0')
a[0] = 'H';        // ✅ fine
The gets() function is gone for a reason — it overflowed everything. Use fgets(buf, size, stdin) and always keep the last byte for '\0'.

32Arrays of Pointers — & Sorting

An array of char* is how C stores a list of strings — each element points to its own string. Sorting such a list swaps pointers, not the data:

CODE
const char *names[] = {"kiwi", "apple", "pear"};
size_t n = sizeof(names) / sizeof(names[0]);

// bubble sort by strcmp — swap the POINTERS
for (size_t i = 0; i < n - 1; i++)
    for (size_t j = 0; j < n - i - 1; j++)
        if (strcmp(names[j], names[j + 1]) > 0) {
            const char *tmp = names[j];
            names[j] = names[j + 1];
            names[j + 1] = tmp;
        }

for (size_t i = 0; i < n; i++)
    printf("%s ", names[i]);   // apple kiwi pear
LIVE — sort the pointers

Each box is a char* pointing at its string — sorting swaps the arrows

Same trick, easier: the standard library's qsort (section 30) does this for you with a comparator. Understanding the pointer-swap version first is what makes qsort feel obvious.

33Linked Lists — Pointers in Action

The rite of passage. A node holds data + a pointer to the next node. The list grows and shrinks at runtime with malloc — no fixed size. Every node must be freed:

CODE — list.c
typedef struct Node {
    int data;
    struct Node *next;    // pointer to the next node
} Node;

void append(Node **head, int value) {
    Node *n = malloc(sizeof(Node));
    n->data = value;
    n->next = NULL;

    if (*head == NULL) { *head = n; return; }

    Node *cur = *head;
    while (cur->next) cur = cur->next;  // walk to the end
    cur->next = n;
}

void print_list(Node *head) {
    for (Node *cur = head; cur; cur = cur->next)
        printf("%d → ", cur->data);
    printf("NULL\n");
}
LIVE — build a list

value

Free the whole list

void free_list(Node *head) {
    while (head) {
        Node *next = head->next;   // save next BEFORE freeing
        free(head);
        head = next;
    }
}
Why Node**? append(&head, 5) needs to change the caller's head — so it takes a pointer to head (a Node**). Same reason as swap() in section 16.

35Debugging & Best Practices

You'll spend more time debugging C than writing it. Arm yourself: compile with warnings, run under valgrind, and step through with gdb:

TERMINAL — the toolkit
$ gcc -Wall -Wextra -g app.c -o app # -g = debug info $ valgrind ./app # find leaks & bad reads ==10== ERROR SUMMARY: 0 errors $ gdb ./app (gdb) break main (gdb) run (gdb) print x # inspect variables live (gdb) next # step one line (gdb) bt # backtrace — where are we?
The segfault recipe
Segmentation fault almost always means: • dereferencing NULL • writing past an array • using a freed pointer • returning a local's address → compile with -g, run in gdb, 'bt' shows the exact line.

Habits that save you

  • Compile with -Wall -Wextra -Werror — warnings are bugs waiting to happen
  • Initialize every variable; check every malloc and fopen
  • Use const for parameters you only read — the compiler then guards you
  • Free in the layer that allocated; set pointers to NULL after freeing
  • Name things honestly: count, not n; functions do ONE job
  • No magic numbers — #define MAX_STUDENTS 50, not 50
When stuck: reduce. Copy the failing snippet into a tiny test program, add printf at each step, and watch where the value goes wrong. Bisect, don't guess.
