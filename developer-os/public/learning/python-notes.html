01What is Python?

04Variables — Named Boxes

A variable is a name for a value. No declaration needed — just assign. Python is dynamically typed: the same name can hold a number now and a string later.

CODE
name = "Lina"      # string
age = 25           # int
pi = 3.14        # float
skills = ["py", "sql"]  # list

# swap two values — one line, no temp variable!
a, b = 1, 2
a, b = b, a
print(a, b)   # 2 1
OUTPUT
2 1

Naming rules

  • Letters, numbers and underscores only — must NOT start with a number
  • Case-sensitive: age and Age are different
  • Convention: snake_case for variables, UPPER_CASE for constants
  • Keywords are reserved: if, for, class… can't be names
Chained assignment: x = y = 0 sets both to 0. But a = b = [] makes both names point to the same list — a classic bug!

15Functions — Reusable Blocks

def defines a function. It takes parameters, does work, and can return a result. A function with no return gives None:

CODE
def greet(name):
    """Return a friendly greeting."""
    return f"Hey {name}!"

def is_even(n):
    return n % 2 == 0

print(greet("Sam"))
print(is_even(10), is_even(7))
OUTPUT
Hey Sam! True False

Rules of thumb

  • Name functions with snake_case verbs: calculate_total()
  • A function should do one job — if it does two, split it
  • Docstrings ("""...""") explain what it does — future-you will thank you
  • Call before define? No — Python reads top-to-bottom, so define first, call after
Early return: you can exit a function at any point with return. Guard clauses (if not valid: return) keep code flat and readable.

16Arguments — Defaults, *args, **kwargs

Python functions are flexible about how they're called. Defaults, keyword arguments, and the two star-prefixed collect-alls cover every calling style:

CODE
def order(item, qty=1, urgent=False):
    return f"{qty}x {item}" + (" ⚡" if urgent else "")

print(order("pizza"))            # 1x pizza
print(order("sushi", 3))        # 3x sushi
print(order("cola", urgent=True))  # keyword!

def total(*nums):        # any number of args → tuple
    return sum(nums)
print(total(1, 2, 3))     # 6

def profile(**info):      # keyword args → dict
    return info
print(profile(name="Ada", lang="Python"))
OUTPUT
1x pizza 3x sushi 1x cola ⚡ 6 {'name': 'Ada', 'lang': 'Python'}

The * trick both ways

nums = [1, 2, 3]
print(total(*nums))    # unpack a list into arguments → 6
d = {"item": "tea", "urgent": True}
print(order(**d))    # unpack a dict into keyword args → 1x tea ⚡
Order matters: defaults can't come before required params: def f(a, b=2) ✅ but def f(a=1, b) ❌ SyntaxError.

17Lambda, map & filter — Functions as Data

A lambda is a tiny anonymous function. It shines when passed to tools like map() (transform every item), filter() (keep some items), and sorted() (custom ordering):

CODE
nums = [1, 2, 3, 4, 5]

squares = list(map(lambda x: x * x, nums))
print(squares)        # [1, 4, 9, 16, 25]

evens = list(filter(lambda x: x % 2 == 0, nums))
print(evens)          # [2, 4]

words = ["kiwi", "apple", "pear"]
print(sorted(words, key=lambda w: len(w)))  # shortest first
OUTPUT
[1, 4, 9, 16, 25] [2, 4] ['pear', 'kiwi', 'apple']

When to use what

ToolResultRule of thumb

filter(f, items)fewer or equal, original items"keep the ones where f is True"

Pythonic note: for one-step transforms, list comprehensions (section 27) are usually more readable. Lambdas win when you need a function object to pass around.

18Scope — Where Names Live

A variable's scope decides who can see it. Python follows LEGB — Local, Enclosing, Global, Built-in. The two rules that trip everyone up: global and nonlocal:

CODE
count = 0          # global

def bump():
    global count   # declare: I want the global one!
    count += 1

def read():
    return count   # reading globals is always fine

bump(); bump()
print(read())     # 2
OUTPUT
2
The classic bug: inside a function, count += 1 WITHOUT global count creates a brand-new local variable called count — and crashes with UnboundLocalError. If you assign to a name, Python assumes it's local.

nonlocal — for nested functions

def outer():
    total = 0
    def inner():
        nonlocal total  # modify the enclosing scope's total
        total += 1
    inner(); inner()
    return total
print(outer())   # 2
Best practice: avoid global — return values instead. Globals make programs impossible to reason about as they grow.

21Working with Files

The with statement opens a file and always closes it, even on errors. Three modes: r read, w write (overwrites!), a append:

with open("notes.txt") as f:

23Classes — Blueprints for Objects

A class bundles data (attributes) and behavior (methods) into a reusable blueprint. __init__ runs when you create an instance, and self is the instance itself:

CODE
class Dog:
    def __init__(self, name):
        self.name = name
        self.energy = 100

    def bark(self):
        return f"{self.name} says WOOF!"

    def play(self):
        self.energy -= 10
        return f"{self.name} plays (energy {self.energy})"

rex = Dog("Rex")
print(rex.bark())
print(rex.play())
print(rex.play())
LIVE — meet Rex

energy: 100/100

Class vs instance

  • self.attr — belongs to each instance (Rex has his own energy)
  • Attributes without self. inside the class body are class-level, shared by all
  • Name convention: classes are CamelCase — Dog, not dog
OOP mindset: a class is a noun with verbs as methods. If you find yourself passing the same data to functions over and over, it's probably a class.

24Inheritance — Reuse & Extend

A child class inherits everything from its parent, then adds or overrides. super() calls the parent's version:

CODE
class Animal:
    def __init__(self, name):
        self.name = name
    def sound(self):
        return "..."

class Cat(Animal):        # Cat IS an Animal
    def sound(self):       # override
        return "Meow!"

class Robot(Animal):
    def __init__(self, name, battery):
        super().__init__(name)   # parent's setup
        self.battery = battery
    def sound(self):
        return f"Beep (battery {self.battery})"

for a in [Cat("Milo"), Robot("R2", 80)]:
    print(a.name, "→", a.sound())
OUTPUT
Milo → Meow! R2 → Beep (battery 80)

Polymorphism in one sentence

The loop above calls sound() on each object — and each does its own thing. That's polymorphism: same call, different behavior, decided at runtime.

isinstance: isinstance(robo, Animal) → True, because a Robot IS an Animal. Check this before forcing a duck-typed object through code that needs a specific interface.

25Magic Methods & Dataclasses

Dunder methods (double-underscore) give your objects superpowers — so len(my_obj), str(my_obj) and my_obj == other just work. And @dataclass writes the boring boilerplate for you:

CODE
class Deck:
    def __init__(self):
        self.cards = ["A", "K", "Q"]
    def __len__(self):
        return len(self.cards)   # len(deck) works!
    def __str__(self):
        return " → ".join(self.cards)  # print(deck) works!

d = Deck()
print(len(d))
print(d)
OUTPUT
3 A → K → Q

@dataclass — zero boilerplate

from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p = Point(1, 2)
print(p)              # Point(x=1, y=2) — __repr__ free!
print(p == Point(1, 2))  # True — __eq__ free!
Common dunders: __init__ construct, __str__ display, __len__ size, __eq__ equality, __repr__ debugging, __getitem__ indexing (obj[0]), __call__ makes objects callable.

26Generators — Lazy & Infinite

A function with yield becomes a generator: it produces values one at a time, pausing between each. Memory stays tiny even for huge sequences — it never builds the whole list:

CODE
def countdown(n):
    while n > 0:
        yield n          # pause here, hand out n
        n -= 1

for x in countdown(3):
    print(x)          # 3, then 2, then 1

# infinite sequence, zero memory
def odds():
    n = 1
    while True:
        yield n
        n += 2

print(next(odds()))  # 1
OUTPUT
3 2 1 1

yield vs return

returnyield
Runsonce, all at oncelazily, one value at a time
Memorywhole result in RAMone value at a time
Can resumenoyes — remembers position!
Use case: reading a 10 GB file line by line, streams, pipelines. If you list() a generator, you defeat the point — consume it in a loop instead.

27Comprehensions — Build Collections in One Line

A comprehension is a loop compressed into an expression. It's the most Pythonic feature there is — read it like English: "build a list where x is in nums if x is even":

CODE
nums = [1, 2, 3, 4]

squares = [x * x for x in nums]
print(squares)      # [1, 4, 9, 16]

evens = [x for x in nums if x % 2 == 0]
print(evens)        # [2, 4]

pairs = {x: x * 2 for x in nums}   # dict!
print(pairs)       # {1: 2, 2: 4, 3: 6, 4: 8}

words = ["hi", "a", "hello"]
long = [w.upper() for w in words if len(w) > 1]
print(long)        # ['HI', 'HELLO']
OUTPUT
[1, 4, 9, 16] [2, 4] {1: 2, 2: 4, 3: 6, 4: 8} ['HI', 'HELLO']
The verbose version (same thing)
squares = []
for x in nums:
    squares.append(x * x)
OUTPUT
[1, 4, 9, 16] — same result, 3 lines vs 1

Nested comprehension (flatten a matrix)

matrix = [[1, 2], [3, 4]]
flat = [n for row in matrix for n in row]
print(flat)   # [1, 2, 3, 4]
Don't overdo it: if a comprehension needs an if AND a nested loop AND a function call, write a normal loop — readability wins over cleverness.

30JSON — The Language of the Web

JSON is how programs exchange data — an API response, a config file, a save game. Python dicts and JSON look almost identical, which makes the conversion trivial:

CODE
import json

player = {"name": "Aria", "level": 7, "items": ["sword"]}

# dict → JSON string (save it, send it)
text = json.dumps(player)
print(text)

# JSON string → dict (load it, use it)
back = json.loads(text)
print(back["name"], back["level"])
LIVE — convert it

Save to a file

with open("save.json", "w") as f:
    json.dump(player, f, indent=2)
Gotchas: JSON needs double quotes, not single; tuples become lists; True becomes true (lowercase). json.loads throws JSONDecodeError on bad input — wrap it in try/except.

31Regular Expressions — Pattern Matching

A regex describes a pattern — an email shape, a phone format, a set of dates. Start small: \d digits, + one-or-more, [...] a character set:

CODE
import re

33Decorators — Wrap a Function

A decorator takes a function, adds behavior around it, and hands back an upgraded version. You've already used them — @dataclass is one! Here's a timer you could actually use:

CODE
import time

def timed(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time() - start:.4f}s")
        return result
    return wrapper

@timed                       # the magic sugar
def slow_thing():
    total = sum(range(10_000_000))
    return total

print(slow_thing())
OUTPUT
slow_thing took 0.4123s 49999995000000

Reading a decorator

@timed is exactly equivalent to slow_thing = timed(slow_thing). The decorator runs at definition time and wraps every future call.

Real-world decorators: Flask routes (@app.route("/")), Django permissions, @property, @staticmethod, @lru_cache for memoization. Once you see the pattern, they're everywhere.

34Recursion — Functions That Call Themselves

A recursive function solves a problem by calling itself on a smaller version of the same problem, until it hits a base case. The classic: Fibonacci:

CODE
def fib(n):
    if n < 2:          # base case — stop here
        return n
    return fib(n - 1) + fib(n - 2)

for i in range(8):
    print(fib(i), end=" ")
# 0 1 1 2 3 5 8 13

n = 10

Iterative version (fast, no recursion depth issue)

def fib_iter(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
Every recursion needs a base case or it runs forever and dies with RecursionError. Also, naive fib(40) is slow — that's why @lru_cache (memoization) exists.
