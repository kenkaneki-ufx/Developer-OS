01What is CSS?

CSS (Cascading Style Sheets) is the language of appearance. HTML builds the skeleton; CSS adds the skin. Same HTML can look completely different with different CSS. There are 3 ways to add CSS to a page:

CODE
<!-- 1. EXTERNAL (best, most used) -->
<link rel="stylesheet"
      href="style.css">

<!-- 2. INTERNAL (inside the head) -->
<style>
    p { color: blue; }
</style>

<!-- 3. INLINE (on the element) -->
<p style="color: red;">Hi</p>
RESULT

External — style.css file: reusable across many pages, cached by browser. Use this 95% of the time.

Internal — a <style> block in the head: fine for one-page demos.

Inline — style attribute: works, but messy. Avoid unless it's a one-off.

Golden rule: external CSS file + class attributes = clean, reusable, professional. Inline styles = quick hack.

02CSS Syntax — the recipe

Every CSS rule is a selector (who to style), then a declaration block of properties (what to change) and values (how to change it):

CODE
p {
    color: #3366cc;     /* property: value; */
    font-size: 18px;
    font-weight: bold;
    text-align: center;
}

.card {                  /* class = dot */
    background: #f0f4ff;
    padding: 20px;
    border-radius: 12px;
}
RESULT

I am styled by the "p" rule

I am styled by the ".card" class rule
  • Selector — which element(s)
  • Property — the thing to change (color, size, spacing…)
  • Value — the setting (blue, 18px, center…)
  • ; — separates declarations (don't forget it!)
  • /* comment */ — notes for humans

03Basic Selectors

Selectors answer one question: "which elements should I style?" The four basics:

CODE
/* element selector — all <p> */
p { color: #0969da; }

/* class — dot. reuse anywhere */
.highlight { background: #fff8c5; }

/* id — hash. ONE element only */
#main-title { color: #cf222e; }

/* universal — everything */
* { margin: 0; }

/* group — same styles, many */
h1, h2, h3 { font-weight: bold; }
RESULT

#main-title → red

p → blue

.highlight → yellow background

p again → blue

.classdotany element with that class (reusable)
#idhashthe ONE element with that id
*starevery element
a, bcommaall a and b (grouping)
Naming: classes use kebab-case (my-card, btn-primary). Never start a class with a number!

Combinators and pseudo-classes — how you target specific elements without adding classes everywhere:

05Specificity & the Cascade

When two rules fight over the same element, the browser scores each selector. More specific wins. The score has three columns: (id, class, element).

CODE
/* scores: (id, class, element) */
p         { color: #0969da; } /* (0,0,1) */
.special { color: #cf222e; } /* (0,1,0) — wins */
#first   { color: #1a7f37; } /* (1,0,0) — wins more */
p.special{ color: #8250df; } /* (0,1,1) — wins all */

/* inline style beats everything: */
<p style="color:black">...</p>

/* !important beats even inline — avoid! */
p { color: #57606a !important; }
RESULT

plain p → blue (0,0,1)

.special → red (0,1,0) beats p

#first → green (1,0,0) beats class

p.special2 → purple (0,1,1) beats all above

Whoever scores highest wins. If scores tie, the LAST rule in the file wins.

Beginner trap: "why isn't my style applying?" — 90% of the time it's specificity. A more specific rule is silently beating yours. Check with F12 → Inspect → Styles.

06Inheritance — styles pass down

Set a property on a parent, and children inherit it — until someone overrides it. Text properties inherit; layout properties (margin, border, size) do not.

CODE
body {
    font-family: Georgia, serif;  /* inherited */
    color: #1f2328;          /* inherited */
    margin: 0;                 /* NOT inherited */
}

.parent {
    color: #8250df;
    border: 2px solid gray;  /* not inherited */
}

/* force inheritance or undo it: */
.child { border: inherit; }   /* yes, take it */
.plain { color: initial; }    /* back to default */
RESULT
Parent — purple, has a border
Child — overrides to red; border NOT inherited (only the parent has it)

Color inherits down the tree. Borders, margins, backgrounds don't.

InheritedNot inherited
color, font-family, font-size, line-height, text-align, visibility margin, padding, border, background, width, height, position
Why it matters: set font-family once on body and the whole site inherits it. That one rule styles everything.

07Colors

CSS has many ways to write a color. The modern ones (hex, rgb, hsl) give you full control — and opacity/alpha adds transparency:

CODE
p {
    color: tomato;              /* 140 named colors */
    color: #ff6347;            /* HEX: RRGGBB */
    color: #f63;               /* short hex (same!) */
    color: rgb(255, 99, 71);    /* red, green, blue */
    color: rgba(255, 99, 71, 0.5); /* + alpha 0-1 */
    color: hsl(9, 100%, 64%);   /* hue, sat, light */
    color: hsla(9, 100%, 64%, 0.5);

    background: transparent;
    opacity: 0.7;          /* fades WHOLE element */
}
RESULT
tomato #ff6347 #f63 rgb() hsl() hex cyan blue
rgba 30% rgba 60% rgba 100%

Pick colors like a designer

  • hsl() is the most intuitive: hue = the wheel (0 red, 120 green, 240 blue)
  • Use rgba/hex-with-alpha for overlays: rgba(0,0,0,0.5) = dark veil
  • opacity fades the whole element including children; rgba fades just the background
  • Tools: coolors.co (palettes), colorhunt.co
Tip: copy the color of anything on the web — F12 → pick the element → click the color square → eyedropper tool.

11The Box Model — every element is a box

This is the most important concept in CSS. Every element is a box made of four layers:

CODE
.box {
    width: 200px;
    height: 100px;

    padding: 20px;   /* INSIDE, around content */
    border: 5px solid #0969da;
    margin: 15px;    /* OUTSIDE, pushes others */
}

/* one value = all sides */
margin: 10px;
/* two: vertical, horizontal */
margin: 10px 20px;
/* four: top, right, bottom, left */
margin: 10px 20px 30px 40px;
RESULT

The layers, outside → in:

margin — transparent space OUTSIDE the border
border — visible edge
padding — space INSIDE the border
content — your text
LayerRole
contentyour text/image
paddingbreathing room INSIDE the box (background color covers it)
borderthe visible edge
marginspace OUTSIDE the box, pushes neighbors away (transparent)
Memory hook: padding = personal space inside, margin = social distance outside. Padding makes a box feel bigger; margin creates gaps between boxes.

12Width, Height & box-sizing

The most famous CSS surprise: with box-sizing: content-box (default), the width you set excludes padding and border. With border-box (what everyone uses), width = everything:

CODE
/* content-box (default): */
.a {
    width: 200px;
    padding: 20px;
    border: 5px solid #0969da;
    /* real total = 200 + 40 + 10 = 250px! */
}

/* border-box (the fix): */
.b {
    box-sizing: border-box;
    width: 200px;   /* stays 200px, */
    padding: 20px;  /* padding shrinks content */
}

/* apply to EVERYTHING: */
*, *::before, *::after {
    box-sizing: border-box;
}
RESULT

Both set to width:200px:

content-box → total 250px (wider!)
border-box → total 200px (as set)

This is why layouts "break" — boxes grow bigger than you planned.

PropertyWhat it does
width / heightsize of the box
min-width / max-widthlimits (max-width: 600px = readable text!)
min-height / max-heightvertical limits
width: autoblock fills its parent by default
margin: 0 autocenter a block horizontally (classic!)
Do this once, in every project: the universal box-sizing: border-box rule above. It's the #1 layout sanity fix.

13Display — block, inline, inline-block

How a box behaves next to its neighbors depends on display:

CODE
/* block: full width, new line (default
   for p, div, h1, ul...) */
div { display: block; }

/* inline: sits in text, no size control
   (default for span, a, strong...) */
span { display: inline; }

/* inline-block: best of both */
.chip {
    display: inline-block;
    width: 120px;   /* CAN size it */
    padding: 10px;
}

/* remove from layout entirely */
.hidden { display: none; }
.invisible { visibility: hidden; }
RESULT

display:none vs visibility:hidden: none removes the box (layout closes the gap); hidden keeps the space but shows nothing. Both hide content — none is used 99% of the time.

14Position — place boxes anywhere

position changes how a box is placed. The five values, each with a live demo:

CODE
.a { position: static; }   /* default, normal flow */

.b {
    position: relative;
    top: 10px; left: 20px;
    /* nudged from its normal spot */
}

.c {
    position: absolute;
    top: 0; right: 0;
    /* relative to nearest positioned
       ancestor (or the page) */
}

.d {
    position: fixed;
    bottom: 10px; left: 10px;
    /* glued to the screen while
       scrolling (like the theme btn!) */
}

.e {
    position: sticky;
    top: 0;
    /* sticks until its parent ends */
}

.badge {
    position: absolute;
    z-index: 10;  /* stacking order */
}
RESULT
static — normal position
relative — nudged 6px down, 14px right
absolute badge pinned to this panel: TOP-RIGHT

fixed = this page's 🌙 theme button (bottom-right, always visible). sticky = the menu bar at the top of this page!

ValueUse for
staticdefault — nothing special
relativenudge the box; also becomes the anchor for absolute children
absolutepin to the nearest positioned ancestor (badges, overlays)
fixedstays on screen (navbars, chat buttons)
stickyscrolls then sticks (section headers)

Absolute needs an anchor: set position: relative on the parent, then absolute children position themselves inside it. Without the anchor, they escape to the page corner — a classic bug!

15Float — the old way (know it, rarely use it)

Before Flexbox, float was how you put text next to an image. It still works — you'll see it in old code. Flexbox/Grid replace it today:

CODE
img {
    float: left;        /* right too */
    margin-right: 12px;
}

/* stop the float leaking: */
.clearfix::after {
    content: "";
    display: block;
    clear: both;
}
RESULT
floated

This text wraps around the floated box — that's what float was built for: magazines! Notice how the text flows along the right side of the box, then fills below it.

The clear:both div stops the wrap. Today: use Flexbox for layouts.

Verdict: understand float so old code isn't scary, but write new layouts with Flexbox and Grid (coming right up).

16Flexbox — align anything, perfectly

Put display: flex on a container and its children become flexible items in a row. This one property ends the centering struggle forever:

    justify-content: center;  /* MAIN axis */

    flex-wrap: wrap;          /* wrap on small */

18Grid — 2D layouts (rows AND columns)

21Responsive Design & Media Queries

One page, every screen. Media queries apply CSS only when conditions are true — like screen width. Resize this window and watch the demo below change!

CODE
/* base: phone-first */
.cards { display: grid;
          grid-template-columns: 1fr; }

/* tablet & up */
@media (min-width: 600px) {
    .cards { grid-template-columns: 1fr 1fr; }
}

/* desktop */
@media (min-width: 900px) {
    .cards { grid-template-columns: repeat(3, 1fr); }
}

/* dark mode preference */
@media (prefers-color-scheme: dark) {
    body { background: #0d1117; }
}
RESULT
1 col on phone
2 cols at 600px+
3 cols at 900px+

🖱️ Drag the window edge — the boxes rearrange live!

  • Mobile-first — write the phone layout first, then min-width queries add more
  • Standard breakpoints: 600px (tablet), 900px (laptop), 1200px (desktop)
  • Never forget the viewport meta: <meta name="viewport" content="width=device-width, initial-scale=1">
  • Check your work: F12 → the phone icon (Device Toolbar)
Modern shortcut: grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)) does responsive columns with zero media queries!

23Animations — @keyframes

Transitions react to a state change. Animations run by themselves, forever or a few times:

CODE
.bounce {
    animation: bounce 2s
        infinite ease-in-out;
    /* name duration repeat */
}

@keyframes bounce {
    0%   { transform: translateY(0); }
    50%  { transform: translateY(-16px); }
    100% { transform: translateY(0); }
}

/* other animation properties */
animation-delay: 1s;      /* wait before start */
animation-iteration-count: 3; /* or: infinite */
animation-direction: alternate;
RESULT
bounce 🔄 pulse

No JavaScript — pure CSS motion. Don't overdo it: motion should help, not distract.

Respect users: add @media (prefers-reduced-motion: reduce) to disable animations for people who get motion sickness. One small rule = inclusive site.

RESULT
  • first-child → red
  • nth-child(2) → blue
  • plain third
  • last-child → bold

Click into the field → :focus:

nth-child(odd/even/n/2n+1) does zebra stripes for free.

Superpower: pseudo-classes mean your HTML stays clean — the CSS targets positions and states by itself. Fewer classes = less to maintain.

28Overflow & Text Tricks

CODE
.scroll {
    overflow: auto;      /* scrollbars */
}

.clip {
    overflow: hidden;    /* cut it off */
}

/* 1-line ellipsis: */
.ellipsis {
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
}

/* 2-line clamp (modern): */
.clamp2 {
    display: -webkit-box;
    -webkit-line-clamp: 2;
    -webkit-box-orient: vertical;
    overflow: hidden;
}
RESULT

This is a very long title that absolutely will not fit on one line so it gets cut with three dots…

white-space + overflow + text-overflow: ellipsis

This paragraph is clamped to exactly two lines. The rest of the sentence is hidden even though it keeps going on and on and on and on and on and on…

-webkit-line-clamp: 2 — great for card previews

Classic bug: content overflowing a rounded card looks broken — fix with overflow: hidden on the card, or the image will poke out of the rounded corners.

.card          /* block */

├── index.html
├── css/
│   ├── reset.css
│   ├── style.css
│   └── responsive.css
└── images/
RESULT

The beginner's file plan:

  • One style.css for a small site (don't over-split)
  • Order inside: reset → variables → base → components → pages
  • BEM keeps class names predictable: card__title--big
  • Comment your sections: /* ===== Navbar ===== */
  • Use a linter/formatter (Prettier) so code stays consistent

A 5-line reset fixes 90% of "why is there extra space?" problems.
